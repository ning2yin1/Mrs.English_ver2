# 端末内保存・二重配布防止・バックアップ

## データ構造

IndexedDB名mrs-english、schemaVersion=1、contentVersion=2026-10-27-v2。ストアと主キー:

|store|key|内容|
|---|---|---|
|profile|singleton|nickname,favoriteMemberId,homeBackgroundId,onboardingStep,onboardingComplete,createdAt,updatedAt|
|settings|singleton|soundEnabled,ttsRate,photoOverlay,reduceMotion,language=ja|
|wallet|singleton|rp（0以上の安全な整数）,xp,revision|
|ledger|eventId|type,amountRP,amountXP,createdAt,runId/packId/periodKey,balanceAfter|
|ownedCards|cardId|level,obtainedAt,favorite,locked|
|team|singleton|motokiCardId,hirotoCardId,ryokaCardId|
|packs|packId|source,status,draws[10],revealCursor,createdAt,grantEventId|
|runs|runId|type,grammarId,difficulty,questionOrder,optionOrders,backgroundId,teamSnapshot,questionIndex,answers,activeElapsedMs,status|
|results|runId|accuracy,speed,english,total,correctCount,stars,rpBreakdown,finishedAt,answerDetails,animationComplete|
|stageBest|grammarId:difficulty|bestEnglish,bestEnglishRunId,bestTotal,bestTotalRunId,bestStars,paidStarMilestone|
|mistakes|exampleId|lastWrongAt,difficulty,lastRunId|
|missions|periodKey:missionId|progress,reviewedExampleIds,claimed,claimEventId|
|calendar|dateKey|completedRuns,correctCount,loginClaimEventId,studyDay|
|meta|singleton|schemaVersion,contentVersion,saveRevision,lastClaimDate,lastStudyDate,streak,lastBackupAt|

全日時はUTC ISO8601、日付/週キーはAsia/Tokyoで生成。数値はNaN・Infinity・負値を拒否。参照カードIDは同梱79IDに限定。未知のコンテンツIDを消去せず、対応しない新版本文の場合は読込停止してバックアップを促す。

## 初回特典の状態機械

notEligible → entitled → granted/revealing → completed。

1. STEP3確定トランザクションでonboardingComplete=true、packs['WELCOME-V1']をentitledで1件だけ作る。既存キーなら何もしない。
2. 開封タップ時readwriteでprofile,packs,wallet,ledger,ownedCards,teamをロック。packがentitledのときだけ抽選し、10件drawsを保存。新規カード付与・重複RP還元・初期編成・ledger['pack:WELCOME-V1']を同じトランザクションに入れる。status=revealing、cursor=0。成功commitを待ってから演出開始。
3. 各カードの表面表示が完了した時点でcursorを次の未確認位置に保存。表示を閉じるだけで付与処理を呼ばない。
4. 途中終了→起動時status=revealingを優先表示。drawsを再抽選せずcursorから再開。全付与は済んでいるので報酬喪失も重複付与もない。
5. 最後の一覧を閉じてcompleted。途中にRPやカードをUI表示しても追加付与しない。最初のcommit前にクラッシュした場合はentitledのまま、再試行で初めて確定。

## 購入・強化・報酬の原子性

購入eventIdはUI操作開始時にUUIDを1度発行し再試行で同じID。IDBトランザクションで残高再確認→減算→抽選保存→新規/重複付与→ledger挿入。並行タブでもreadwriteトランザクションとeventIdユニーク制約で二重差引を防止する。画面ボタン無効化だけに頼らない。

強化eventIdも同じ。残高、現在Lv、MAX、対象カードの一致を再確認してRP減算とLv+1を同一commit。古い画面の金額を信頼しない。

結果確定はeventId='finish:'+runId。runがactiveで10問（復習は予定数）すべて回答済みのとき、results追加、wallet/XP加算、stageBest更新、星差分のpaidMilestone更新、mistakes、calendar、missions、run.status=completed、ledgerを同一トランザクション。既存finishがあれば同じ結果を返すだけ。完了ボタンやアニメーション再表示で付与しない。途中の回答正誤はrunへ自動保存するが、ミッション・通貨・XP確定はfinishだけ。

ミッションeventId='mission:'+periodKey+':'+missionId、ログインeventId='login:'+dateKey。progress・claimed・期間とwallet加算を同じトランザクション。日付が切り替わる直前に開いたダイアログでも押下時の期間で再検証。星報酬キーはstageIdで難易度を含む。

## 自動保存と競合

選択肢クリック・ブロック移動は変更を直列保存し、判定前に最新入力を確定。activeElapsedMsは250msごとの永続化を目安とし、visibilitychange・pause・回転時にも同期。強制終了直前の最大250msの揺れを仕様上許容するが、再開時にタイマーをゼロに戻さない。終了前に保存を待つと無応答になる状況では画面に「保存中」を残す。

アクティブなrunは1端末1件。BroadcastChannel等で他タブに通知し、古いタブでは編集を停止して再読込を促す。台帳に連番saveRevisionを持たせる。Cache APIは画像/教材専用、ユーザーセーブをキャッシュ更新で消さない。

## バックアップ形式

{format:'MrsEnglishBackup',schemaVersion:1,contentVersion,exportedAt,payload,sha256}。payloadは上表全ストア（画像バイナリを除く）。sha256はUTF-8の正規化payload JSONに対して計算し破損検出に使う。署名やチート対策ではない。バックアップファイル名mrs-english-backup-YYYYMMDD-HHmm.json。

インポートは最大20MB、UTF-8JSON、キーの型・ID参照・カードLv上限・3人編成・RP整合性・重複eventId・結果数を検証。新しいschemaVersionは拒否。既存セーブを先に自動バックアップしてから、全ストアを一括置換。マージしない。失敗したらrollbackして現セーブ保持。完了後はopenPack/runを復元する。旧いバックアップへ戻すと当時の状態へ戻ることを確認文で説明。完全ローカル環境でバックアップ巻戻しまで禁止する仕組みは設けない。

## 障害試験

初回権利発行直前/直後、抽選commit直前/直後、3枚目表示直後、購入連打、強化同時タブ、finish直後の再起動、結果連打、週境界、保存容量不足、不正JSON、別バージョン取込、Service Worker更新中、オフライン再起動を必須受入試験にする。1つの権利に対してledgerの付与イベントが最大1件であることを検証する。
